1. Architectural Overview & Pillars

CreaterHub connects local businesses with authentic, verified Instagram creators within precise geographic radii (1 km – 50 km). Built under a strict "REAL DATA FIRST. ZERO FAKE DATA" architectural guarantee, all follower counts, engagement metrics, and media items originate exclusively from official Meta Graph API v19.0 connections or multi-tier search crawlers, with zero synthetic guesswork.

🛡️ 1. Real Data First Guarantee Official OAuth exchange, long-lived token vault (AES-256), fallback web crawlers, transparent data provenance.
📍 2. Haversine Geospatial Discovery 1km, 5km, 10km, 25km radius filtering with Leaflet interactive OpenStreetMap discovery.
🎯 3. Multi-Factor Compatibility Matching Objective 0–100% score based on distance, engagement compliance, audience tier, and niche overlap.
🔒 4. 6-Stage Escrow Lifecycle APPLIED ➔ ACCEPTED ➔ ESCROW_LOCKED ➔ PROOF_SUBMITTED ➔ APPROVED ➔ ESCROW_RELEASED.

4. Backend Architecture (`server/`)

The backend is built with Node.js 22 and Express 5, utilizing the built-in node:sqlite engine in WAL (Write-Ahead Logging) mode for zero-dependency local execution, with plug-and-play PostgreSQL support.

4.1 REST API Routes (`server/routes/`)

Route Module Endpoint Prefix Operations & Security Rules
auth.cjs /api/auth User registration (bcrypt 10 rounds), login, JWT signing, profile resolution, and active role switching.
creators.cjs /api/creators Creator listing with geospatial filters, media kits, direct pitch dispatch, and profile editing.
brands.cjs /api/brands Brand profile management, active campaign summaries, and brand metrics.
campaigns.cjs /api/campaigns Campaign publishing, status transitions, Haversine geospatial proximity search, and match calculations.
applications.cjs /api/applications Campaign pitch submissions, subscription quota checks, reward ceiling enforcement, and brand status updates.
collaborations.cjs /api/collaborations Active collaboration state machine, deliverable proof URL submissions, revision requests, and escrow payouts.
instagram.cjs /api/instagram Meta Graph OAuth token exchange, long-lived 60-day token vault, handle validation, and multi-tier crawler sync.
ai.cjs /api/ai Gemini AI-powered creator profile scoring and automated campaign brief generation.
messages.cjs /api/messages Thread conversations, unread message counts, and direct communication between collaborating parties.
payments.cjs /api/payments Escrow transaction ledger, simulated escrow locking, and verified payout records.
subscriptions.cjs /api/subscriptions Tier definitions (Silver, Gold, Diamond), monthly application quota verification, and simulated tier upgrades.
admin.cjs /api/admin System-wide KPIs, user ban/unban moderation, dispute resolution, and Meta API sync audit logs.

4.2 Core Micro-Services (`server/services/`)

InstagramService.cjs Official Meta Graph API v19.0 client. Exchanges short-lived to 60-day tokens, queries /me/media, and calculates genuine engagement rates.
instagramPublicFetcher.cjs Robust multi-tier web crawler (Google, Yahoo, Bing, Jina.ai) for live follower and media extraction when Meta OAuth is in development mode.
AIAnalysisService.cjs Google Gemini GenAI prompt construction. Generates structured JSON scoring (0–100), key strengths, and monetization advice.
MatchingService.cjs Calculates spherical geodesic distance using the Haversine formula and computes 6-factor compatibility scores between brands and creators.
PaymentService.cjs Abstracted escrow engine. Implements Development Escrow Simulator with immutable transaction references and audit logs.
TokenEncryptionService.cjs AES-256-GCM symmetric encryption for securely storing sensitive Meta Graph API OAuth user tokens in the database.

5. Relational Database Architecture (`server/db/`)

The persistence layer consists of 20 normalized relational tables enforcing strict foreign keys, cascade rules, and timestamp tracking:

Table Name Primary & Foreign Keys Domain & Purpose
users id (PK), email (UNIQUE) Authentication credentials, password hashes, role designation (creator, brand, admin).
creator_profiles id (PK), user_id (FK -> users) Bio, content pillars, coordinates (lat/lng), subscription tier, average rating, rate card.
brand_profiles id (PK), user_id (FK -> users) Company name, category, headquarters, store locations, website URL, verified status.
instagram_accounts id (PK), creator_id (FK) Meta OAuth tokens (AES-256 encrypted), token expiration timestamp, Instagram Business User ID.
instagram_metrics id (PK), instagram_account_id (FK) Verified live follower counts, following, post counts, calculated engagement rates.
instagram_media id (PK), instagram_account_id (FK) Synced recent media posts, captions, like/comment counts, media URLs, timestamps.
ai_creator_analyses id (PK), creator_id (FK) Gemini AI structured assessment JSON, pillar scores, consistency analysis, monetization tips.
campaigns id (PK), brand_id (FK -> brand_profiles) Title, reward per creator, geographic coordinates, target radius, deliverables JSON, status.
campaign_applications id (PK), campaign_id (FK), creator_id (FK) Creator pitch message, proposed rate, match score, status (PENDING, SHORTLISTED, ACCEPTED).
collaborations id (PK), application_id (FK) Active partnership state machine, current step (1 to 4), delivery deadlines, completion flags.
deliverables id (PK), collaboration_id (FK) Proof URLs (Instagram Reel/Story links), submission notes, brand approval/revision status.
payments id (PK), collaboration_id (FK) Simulated escrow ledger, held/released status, amount, transaction reference codes.
conversations id (PK), brand_id (FK), creator_id (FK) Direct communication channels between brands and creators for pitches and negotiation.
messages id (PK), conversation_id (FK) Direct chat messages with timestamp ordering and read status flags.
reviews id (PK), collaboration_id (FK) Bidirectional 1–5 star ratings and written performance feedback.
notifications id (PK), user_id (FK -> users) In-app notifications for direct pitches, escrow movements, proof reviews, and messages.
admin_actions id (PK), admin_id (FK -> users) Audit log of platform moderation (account suspensions, dispute resolutions).
refresh_logs id (PK), account_id (FK) Meta Graph API sync attempts, duration, error codes, and audit records.
